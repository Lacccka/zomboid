## Вердикт

Фокус: proximity scanner, prompt, branching dialogue, behavior, gifting and trader UI.

Borrow UI/proximity ideas only. This report is a concrete security checklist for our server validation layer.

## Архитектура

| Слой | Что находится в слое |
|---|---|
| CLIENT | scans nearby moving objects, opens dialogue UI, executes response branches/sounds and submits behavior/trade/gift commands. |
| SERVER | has command handlers for dialogue, behavior, trading and gifting, but important award paths trust client payloads. |
| SHARED | dialogue definitions/session manager/behavior definitions and conditions are shared. |

## Network

- NPCDialogue/StartApproach and RemoveRequiredItem
- NPCTrading/AwardItems and RemoveItems
- NPCGifting/AwardGift
- NPCBehavior/ExecuteBehavior

Вывод по authority: серверный слой присутствует, но доверие проверяется по каждому handler отдельно.

## Persistence и identity

dialogue history is placed in player ModData; active sessions are a Lua table keyed by player online ID; proximity identity uses tostring(npc).

## Полезные механики

- clean proximity scanner
- interaction prompt
- multi-tier branching UI
- voice/sound hooks
- content-oriented condition/behavior API

## Риски и anti-patterns

- critical: AwardItems/AwardGift can add client-selected itemType and quantity
- StartApproach lacks server distance/session validation
- RemoveRequiredItem accepts client-selected item/flag
- online ID/tostring object identity is not persistent
- do not reuse its network/reward design
