## Вердикт

Фокус: persistent named sister Bandits NPC, dialogue, quests, map/radio/story and vehicle companion state.

Promote for end-to-end Bandits narrative integration; treat client-completion/snapshot commands as anti-patterns to harden.

## Архитектура

| Слой | Что находится в слое |
|---|---|
| CLIENT | quest panel, festival Bandit dialogue, sister interaction, idle/vehicle dialogue, map and radio presentation; reports quest/NPC snapshots. |
| SERVER | spawns/restores sister, festival population and vehicle, receives Sister* commands and stores world state. |
| SHARED | quest definitions/state helpers and sister dialogue/programs are shared. |

## Network

- SisterSpawn/SisterCallOver/SisterAppearance/SisterDied/SisterInventorySnapshot/SisterVehicleSnapshot/...
- QuestStarted/QuestCompleted
- entity transmitModData

Вывод по authority: серверный слой присутствует, но доверие проверяется по каждому handler отдельно.

## Persistence и identity

ModpackFestivalSpawn Global ModData plus player/bandit/vehicle ModData; quest state helpers transmit player ModData.

## Полезные механики

- closest authored Bandits2 NPC→dialogue→quest story
- persistent companion snapshots
- idle/vehicle dialogue
- quest panel
- map/radio integration

## Риски и anti-patterns

- client reports QuestCompleted and full inventory/vehicle snapshots
- server validation of those payloads is insufficient as a generic framework
- scenario is tightly hard-coded
- B42.18 only
