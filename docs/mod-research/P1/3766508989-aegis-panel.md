## Вердикт

Фокус: large tabbed UI framework, roles/rights, factions/relations, zones, logs, notifications and player/server panels.

Reference UI/page composition, rights checks and audit logging for future quest administration tooling.

## Архитектура

| Слой | Что находится в слое |
|---|---|
| CLIENT | AegisWindow/pages maintain a docked multi-tab panel and submit narrowly named commands. |
| SERVER | many domain-separated handlers enforce Aegis rights/admin access and return projections/results. |
| SHARED | AegisShared defines module/rights/helpers; most domains are split client/server files. |

## Network

- Aegis/AegisAdmin/AegisPlayer modules
- panelSession/rightsReq
- roleList/roleSave/roleAssign
- factionList/relations
- log list/read
- many targeted sendServerCommand responses

Вывод по authority: серверный слой присутствует, но доверие проверяется по каждому handler отдельно.

## Persistence и identity

server files/ModData back roles, settings, stats, logs and retention; persistence strategy varies by subsystem.

## Полезные механики

- excellent large UI composition
- role-based command authorization
- domain-separated server handlers
- audit logs
- session/open-panel tracking
- faction/relations UI

## Риски и anti-patterns

- admin tool, not a quest framework
- huge privileged surface requires per-command audit
- do not expose admin projections to ordinary players
- license not found in package
