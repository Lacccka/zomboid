QP Supply Requests v0.6.6
- Added optional server-only integration with QP Survivor Reputation v0.4.1 Community automation.
- Awards one fixed Community completion reward to each survivor with a positive frozen final contribution.
- Self-created requests are rejected by QP Survivor Reputation exploit protection.
- Added a persistent deterministic request ID for stable duplicate protection.
- Existing requests receive a deterministic fallback ID when next written.
- No reward is attempted until the request is permanently completed.
- No retroactive award is generated when Community automation is disabled at completion.
- QP Survivor Reputation remains optional; Supply Requests behavior is unchanged when it is absent or disabled.

QP Supply Requests v0.6.5
- Fixed active contribution totals increasing when the same item was repeatedly removed and deposited again.
- Fixed protected multiplayer containers showing the warning too late, after the vanilla item transaction had already moved the item.
- Protected withdrawals are now rejected in ISInventoryTransferAction:isValid() before createItemTransaction() starts, while retaining the transfer-stage fallback and server-side intent rejection.
- Contribution rows now represent net credited supplies currently retained in an incomplete request, not gross transfer actions.
- Registers exact item-ID intents for both deposits and withdrawals before multiplayer transactions start.
- Persists active item ID to contributor ownership so removing a credited item removes the correct contributor credit.
- If an older request has no item ownership data, withdrawal reconciliation falls back safely without allowing total credit to exceed active progress.
- Removing excess items that do not reduce request progress does not erase valid contribution credit.
- Contribution history freezes permanently when the request completes, so collection after Release Supplies does not alter the completed record.
- Preserved multi-item requests, current-admin permissions, protected collection, item-ID deposit verification, migration, persistence, Build 41/42 parity, and all six languages.

QP Supply Requests v0.6.4
- Replaced late transferItem-only attribution with pre-transaction InventoryItem ID intents.
- Registers every selected donation before the vanilla multiplayer item transaction starts, including items later merged into one transfer action.
- The server credits a contributor only after the exact registered item ID appears in the attached request container.
- Canceled or failed transfers receive no credit.
- Holds final completion briefly in memory so late network intent packets are credited before the request closes.
- Keeps v0.6.3 transfer protection as a fallback and preserves multi-item requests, current-admin permissions, protected collection, migration, persistence, Build 41/42 parity, and all six languages.

QP Supply Requests v0.6.3

- Uses the actual item passed to each transferItem call instead of ISInventoryTransferAction.self.item, which can remain pinned to another item in a multi-item transfer action.
- Restores complete contributor rows for every requested item delivered through the same inventory transfer batch.
- Preserved v0.6.2 request-level batching, current-admin permissions, protected collection flow, migration, persistence, Build 41/42 parity, and all six languages.

QP Supply Requests v0.6.2
