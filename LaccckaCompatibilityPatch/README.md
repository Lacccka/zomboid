# Lacccka B42.20 Compatibility Patch

Compatibility and localization layer for the Project Zomboid **Build 42.20.x** mod set maintained in this repository.

Current patch version: **1.6.0**  
Mod ID: `LaccckaB4220Compat`  
Workshop item: `3782987959`

> This is a compatibility patch, **not a modpack**. The original Workshop mods must be installed separately. The patch only supplies targeted fixes, compatibility shims, failure-isolation guards, Linux dedicated-server workarounds, and localization/UI improvements.

## What the patch fixes

### Bandits

The patch contains several Build 42.20 and multiplayer fixes for Bandits:

- provides the missing dedicated-server `BanditZombie.GetInstanceById()` contract used by Bandits server commands when the original implementation only exists in client Lua;
- prevents the wanderer scheduler from calculating progression from a nonexistent player when a dedicated multiplayer server is empty;
- rejects transient/despawned `IsoZombie` objects that temporarily have no square before they enter Bandits client caches, preventing later combat/update code from dereferencing an invalid square;
- patches Bandits farming zombie actions such as watering and stomping so B42.20 Farming/API failures are isolated instead of repeatedly throwing from zombie task processing;
- restores the legacy character-screen module path expected by Bandits after the B42 UI module layout changed;
- supplies Russian localization used by the server/mod set;
- on Linux, works around lowercase `AnimSets` / XML inheritance paths generated by the B42.20 XML resolver.

Important implementation files include:

- `42/media/lua/server/BanditServerWanderers.lua`
- `42/media/lua/server/zzz_LCC_BanditsDedicatedServerGuard.lua`
- `42/media/lua/client/BanditZombie.lua`
- `42/media/lua/client/ISUI/ISCharacterScreen.lua`
- `42/media/lua/shared/ZombieActions/`

### Lifestyle

The patch extends and stabilizes Lifestyle on B42.20:

- supplies safe shared/server placeholders for Lifestyle bathtub and shower helpers that are otherwise client-only when shared timed actions load;
- fixes bathtub approach logic for west-side entry cases where the original helper can choose an unusable side;
- exposes Lifestyle **Yoga** progress in the normal character skill panel while reading the authoritative Lifestyle hidden-skill data rather than creating a second progression system;
- preserves the complete upstream Lifestyle perk registration (`Lifestyle`, `Art`, `Cleaning`, `Dancing`, `Meditation`, `Music`) while adding Yoga;
- adds concise player-facing Russian descriptions for Lifestyle skills, including important Meditation and Music level milestones;
- includes broad Russian localization for Lifestyle UI, items, recipes, sandbox settings, ambitions, art, music, meditation, Yoga, tutorials and related systems;
- on Linux, works around lowercase mod, `AnimSets`, directory and mixed-case XML filename lookups.

Yoga remains controlled by Lifestyle itself. The patch only exposes its level/XP in the standard skill UI and does not duplicate gameplay XP or migrate saves.

### Modern Firearms System (MFS)

MFS installs a 3D-item cursor override from a server-side directory even though the cursor class does not exist on a dedicated server. The patch keeps that compatibility code client-only and safely restores weapon-part render state when required by the 3D placement cursor.

This prevents the MFS compatibility layer from failing merely because dedicated-server Lua does not have the client cursor API.

### Standardized Vehicle Upgrades 3 / TsarLib

Build 42 changed several module names and locations used by SVU3/TsarLib integrations. The patch supplies compatibility shims for the older paths still expected by dependent mods, including the `ATA2Tuning2` -> `ATATuning2` transition.

It also keeps PZK/SVU support tables reachable from the legacy shared paths expected by existing integration code.

On Linux, TsarLib is also covered by the lowercase `AnimSets` compatibility preflight because B42.20 has been observed resolving inherited animation XML through a different path case than the files stored by the Workshop mod.

### PZK vehicle mods / PZK Carzone

The patch restores several pre-B42 module paths still required by PZK vehicle integrations:

- root-level `ISBaseTimedAction` -> B42 `TimedActions/ISBaseTimedAction`;
- legacy `Vehicle/ISVehiclePartMenu` and `Vehicle/ISUI/ISVehiclePartMenu` -> B42 `Vehicles/ISUI/ISVehiclePartMenu`;
- legacy `utils/pzkZonesFunction` -> current `pzkUtils/pzkZonesFunction`;
- shared `SVU3_PZKVLCCars_Stuffs` -> the current `OtherModsSupport` location.

These are compatibility redirects rather than forks of the original PZK files.

### zRe / zRe Vaccine stack

The zRe engine still references the old root-level `BodyLocations` module. The patch redirects that legacy import to the B42 `NPCs/BodyLocations` location so the zRe stack can continue loading without carrying a copied vanilla implementation.

### Aegis Panel

The patch protects Aegis-related inventory transfers from invalid transfer actions where the item, source container or destination container is already missing. Invalid actions are rejected before the original transfer validator dereferences them.

The original validator remains authoritative for valid actions; the patch only adds the nil-container precheck.

### Federal Ranger's Chimera

The patch fixes the Chimera ghillie clothing extra-menu data mismatch used by `Ghillie_Top` / `Ghillie_Top_FaceHide` variants. It normalizes the affected extra/options lists before the vanilla clothing context menu processes them, preventing the broken menu state without replacing the whole inventory UI.

### Legacy Build 42 callback compatibility

Build 42.19+ moved the recipe-magazine item callback from the older `SpecialLootSpawns.OnCreateRecipeMagazine` entry point to `ItemCodeOnCreate.onCreateRecipeMagazine`.

The patch provides a compatibility bridge only when the legacy callback is absent, allowing older item scripts to continue working without replacing an implementation restored by the game or another mod.

## Compatibility guard design

Most small runtime fixes use `LCC/Guard` instead of blindly monkey-patching another mod.

A guarded compatibility fix normally:

1. checks that the expected upstream table/function/API exists;
2. installs only the minimum missing shim or wrapper;
3. leaves a newer upstream implementation untouched when possible;
4. disables only that compatibility feature when its assumptions are no longer valid;
5. logs the result using `[LCC][Guard][OK]`, `[WARN]` or `[DISABLED]` diagnostics.

This is intended to make upstream mod updates fail visibly and locally instead of silently corrupting unrelated systems.

## Platform support

The gameplay/Lua side of the patch is intended to be platform-neutral and is supported on **Windows and Linux**.

Windows does not require the Linux filesystem workaround. Linux-specific workarounds live in the repository launcher so they do not change Windows behavior.

### Linux dedicated server: B42.20 XML/AnimSets case-sensitivity

Build 42.20 can lowercase filesystem components while resolving animation XML `x_extends` paths. Windows normally hides the mismatch because its common filesystems are case-insensitive; Linux does not.

The problem has been reproduced in server logs for:

- Bandits;
- Lifestyle;
- Escape from Kentucky4215;
- tsarslib.

The resolver can lowercase the mod directory, `AnimSets`, nested directories and, in some cases, the XML filename itself. Lifestyle is an important example because a file such as `LSKnifeDefault.xml` can be requested as `lsknifedefault.xml`.

The repository provides:

```text
server/linux/start-server.sh
```

Before and during Project Zomboid startup it:

- locates the confirmed affected Workshop mods;
- creates safe lowercase aliases for affected mod directories;
- creates `animsets -> AnimSets` aliases for each existing media tree;
- creates lowercase aliases for mixed-case directories and XML filenames inside affected `AnimSets` trees;
- checks `common/media`, `42/media`, `42.20/media` and root `media` layouts;
- keeps required aliases alive during the first 180 seconds because Project Zomboid performs its own Workshop pass after launcher startup and Steam may refresh a mod directory;
- creates `${HOME}/Zomboid/mods` so the dedicated-server file watcher does not throw solely because the optional local-mod directory is absent;
- creates `logs/jvm/` for JVM diagnostics;
- writes launcher diagnostics to `logs/jvm/launcher.log`.

The upstream Workshop content is not replaced. Existing conflicting files/symlinks produce an error rather than being overwritten.

Copy the launcher to the Project Zomboid dedicated-server root next to `ProjectZomboid64` and start the server through it, for example:

```bash
bash start-server.sh -servername servertest
```

For Linux compatibility debugging, keep both the normal server console and:

```text
logs/jvm/launcher.log
```

## Load order

`mod.info` declares `loadafter` relationships for mods whose Lua/UI behavior is patched.

`LaccckaB4220Compat` should load after the supported mods it patches. Do not move the compatibility patch to the beginning of `Mods=` simply to make it load earlier.

The patch does **not** replace dependency management in the original mods; it only establishes the ordering required by its own late compatibility overrides.

## Known issues / current workarounds

### Linux dedicated server -> Windows client Lua checksum

The current B42.20 Linux dedicated-server setup can falsely reject a Windows client during `DoLuaChecksum` even when the reported Workshop file physically exists on the client.

This has been reproduced in the current server/client setup. The patch does **not yet** claim to repair the game's Java checksum implementation.

For the affected test server:

```ini
DoLuaChecksum=false
```

is currently a temporary workaround. Restoring checksum validation is a separate compatibility task and remains on the backlog.

### Existing world MetaGrid warnings

Warnings such as duplicate/invalid room `metaID` entries from an existing world are tracked separately. They are not currently treated as a compatibility-patch or launcher fix because they concern saved world/MetaGrid state and need independent analysis.

## Automatic audits

The repository contains automated checks intended to catch compatibility regressions when Project Zomboid or an upstream mod changes.

`.github/workflows/lifestyle-translation-audit.yml` validates Lifestyle translation/Yoga contracts.

`.github/workflows/compat-contract-audit.yml` validates high-risk compatibility assumptions, including:

- strict upstream contracts for selected full-file compatibility overrides;
- rejection of Lua-style `--` comments in `media/perks.txt` because the B42 `CustomPerks` parser treats them as an invalid block;
- preservation of the complete upstream Lifestyle perk list plus Yoga;
- `bash -n` syntax validation for the Linux launcher;
- presence of the confirmed affected Linux mod list, recursive casefold support, startup alias keeper and launcher diagnostics;
- required Lifestyle skill descriptions and Meditation milestones;
- descriptions for the canonical vanilla/Build 42 skill keys;
- rejection of developer-facing implementation jargon in player skill descriptions.

## Test checklist

After a patch/launcher update:

1. On Linux, copy the latest `server/linux/start-server.sh` to the PZ server root and start the server through it.
2. Save `logs/jvm/launcher.log` and verify the compatibility preflight reports no conflicts.
3. Verify the server log no longer contains lowercase-path `FileNotFoundException` failures for confirmed affected Bandits/Lifestyle/Escape from Kentucky/tsarslib animation XML.
4. Verify `/home/.../Zomboid/mods` no longer produces a `DebugFileWatcher.registerDir` error when the launcher can create it.
5. Verify the server log does not contain `CustomPerks.readFile ... unknown block type "--"`.
6. Connect a client and confirm Bandits runtime/scheduler activity does not produce the previously patched dedicated-server/cache/farming failures.
7. On a Russian client, open **Персонаж -> Навыки** and verify the vanilla/B42 skill descriptions.
8. Open **Образ жизни** and verify descriptions for Искусство, Уборка, Танцы, Медитация, Музыка and Йога.
9. Verify Meditation clearly lists the 3 / 6 / 10 milestones and Yoga contains only useful player-facing effects.
10. Complete at least one Yoga pose and confirm Yoga XP/level updates in the normal skill panel.
11. Reconnect and confirm the same Yoga progress is restored from Lifestyle data.
12. Review `[LCC][Guard]` messages and make sure no expected compatibility feature is unexpectedly disabled.

## Non-goals

This project does not try to silently rewrite every warning produced by a large modpack. Fixes are added when an error is reproducible, attributable to a specific compatibility break, and can be corrected without unnecessarily forking the upstream mod.

Likewise, the Linux launcher does not create lowercase aliases for every Workshop mod by default. The affected list is deliberately restricted to mods for which the B42.20 case-sensitivity failure has been reproduced in logs.
